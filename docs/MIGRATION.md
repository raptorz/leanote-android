# Flutter 移动端迁移状态

## 当前结论

Flutter 客户端的主体迁移已经完成，笔记本删除和全局标签删除/重命名已接入；在线历史正文、格式和附件集合恢复已接入。Flutter 客户端用一套业务代码支持 Android 和 iOS，只使用 Gemsnote API2 v1.0.0；`legacy-android/` 保持只读，仅作为旧行为参考。客户端不支持旧 `/api`，不提供公开注册，也不迁移旧 Android SQLite 数据。

服务端已修复部分阻塞问题：笔记本同步删除、空标签清除、全局标签删除的 USN 与笔记联动、历史版本格式及文件元数据均已补齐。移动端已接入笔记本删除、全局标签管理、空标签清除和历史编辑器格式恢复。新服务端通过 FilesComplete 标记完整快照并保留附件原件，移动端已接入完整恢复；旧历史仍只支持正文恢复。共享内容统一只读，只有原作者可以修改原文；共享者可以把正文、图片和附件复制到本人笔记本，再编辑独立副本。

详细的逐批实现和验证记录保存在根目录 [MIGRATION.md](../MIGRATION.md)。本文用于说明当前完成度和剩余工作。

## 本轮目录管理

- 笔记本菜单可删除已同步的空笔记本。子笔记本、活动笔记、待同步修改和过期版本会阻止删除；通过正常同步接收服务端 tombstone。请求响应丢失后，下次同步可确认结果。
- 标签菜单支持全局删除和重命名（目标已存在时合并），处理活动笔记和回收站笔记。重命名先同步，再将引用替换写入本地事务，上传成功后才删除旧标签。上传失败保留 dirty 队列，同步后重试同一重命名即可继续。
- API2 无原子标签重命名接口，该流程由多个请求组成，不能保证其他设备同时编辑标签时的原子性；跨端并发仍需真实服务端验收。

## 维护规则

- Flutter 的所有服务端通信必须使用 API2，并与 desktop 的 API 用法保持一致。
- `legacy-android/` 不再修改。
- 功能状态变化先更新根目录 `MIGRATION.md` 的实现记录，再同步更新本文的结论和剩余事项。
- 发布要求分别见 [RELEASE.md](RELEASE.md)、[ANDROID_SHARING.md](ANDROID_SHARING.md) 和 [IOS_SHARING.md](IOS_SHARING.md)。


## 三端历史恢复修复

服务端新增 FilesComplete 和带 USN 的 `/api2/note/restoreHistory`。在线历史菜单增加“恢复正文和附件”，检查本地待同步笔记及未处理附件，恢复成功后正常同步；失败不制造本地附件集合。离线历史仍可恢复正文与编辑器格式，完整集合恢复只在线提供。此前服务端物理删除附件的阻塞已修复，历史上已丢失的文件不在可恢复范围内。服务端、Web 与 desktop 同步修改另见各仓库提交。
