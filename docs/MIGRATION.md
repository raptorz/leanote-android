# Flutter 移动端迁移方案

## 目标

在 `mobile-app` 根目录维护新的 Flutter 客户端，用一套业务代码支持 Android 和 iOS。旧 Java Android 工程归档在 `legacy-android/`，只作为功能清单和交互参考。

新客户端以 desktop 的离线优先模型为基础，同时针对手机小屏重新设计导航，不直接照搬桌面三栏布局。API 固定使用 API2 v1.0.0，不兼容旧 `/api`，也不迁移旧 Android SQLite 数据；用户首次登录后从服务端重新建立缓存。

## 架构

- `core/api`：API2 JSON 客户端、错误分类和版本协商
- `domain/models`：账号、笔记本、笔记等领域模型
- `data/database`：每账号隔离的 SQLite 离线数据
- `data/session`：系统安全存储中的 token
- `sync`：上传本地 dirty 数据、拉取 USN 增量、重新同步和附件后台任务
- `repositories`：组合网络、缓存和同步，向界面提供稳定操作
- `ui`：适配手机的页面和组件

账号缓存主键由规范化服务端地址和服务端用户 ID 共同组成。任何笔记、笔记本、标签及附件与服务端交互时使用服务端 ID，本地主键仅用于数据库内部关系。

## 小屏交互

已接入本地待上传状态：笔记标题以深绿点标记，立即同步按钮显示浅绿点。
状态仅依据当前账号 SQLite 的 dirty 数据；成功上传后清除，即使后续下载失败。
同步期间发生的新编辑仍保留标记。同步失败在工作区或笔记列表顶部保留提示，
可关闭或重试；笔记列表也可直接发起同步。不包含后台自动同步或冲突自动合并。

手机端采用逐层导航：工作区/标签/搜索 → 笔记列表 → 笔记详情或编辑。笔记本树在独立页面展开，常用的新建、同步和搜索放在页面工具栏或浮动按钮中。平板宽度充足时可逐步增加双栏布局，但不以桌面三栏作为手机最低布局。
